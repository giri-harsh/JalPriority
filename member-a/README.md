# JalPriority AI — Member A ("Need → Plan")

Member A's half of JalPriority AI: **what is happening, who needs water, and the optimal tanker plan with reasons.**
It owns the scenario / prediction / optimization / explanation engine (`jp_a`, FastAPI on **:8001**, routes under `/a/v1`)
and two dashboard screens (**Crisis snapshot**, **Dispatch plan**) that Member B's shell mounts.

> **SYNTHETIC DATA · SIMULATION RESULTS.** Every scenario, training row and truth value in this repository is generated by a
> seeded simulator. Model metrics are measured on synthetic data and are **never** real-world accuracy.

User stories covered: US-1 (crisis snapshot), US-2 (predicted shortage), US-3 (ranked allocation with litres),
US-4 (tanker assignment and stop order), US-5 (plain-language reasons). Contract: [`../contracts/CONTRACT.md`](../contracts/CONTRACT.md) v1.0.0 (frozen).

## Quick start

Prerequisites: Python 3.11 or 3.12 (the pins do not support 3.13+), Node 20+, Git Bash on Windows.

```bash
cd member-a
uv venv -p 3.12 .venv                       # or: python3.12 -m venv .venv
uv pip install -p .venv/Scripts/python.exe -r backend/requirements.txt -r backend/requirements-dev.txt
uv pip install -p .venv/Scripts/python.exe -e backend --no-deps
#   (Linux/macOS: .venv/bin/python;  plain pip: .venv/bin/pip install -e backend -r backend/requirements-dev.txt)
cp .env.example .env                        # dev defaults; SHARED_* are contract-owned dev values

bash scripts/generate_data.sh               # deterministic: 3 seed scenarios + training CSVs + hidden truth
bash scripts/train_model.sh                 # trains XGBoost, writes models/shortage_xgb_v1.json + model_meta.json
.venv/Scripts/python.exe -m pytest          # unit + contract + property + e2e

bash scripts/run_dev.sh                     # API on http://localhost:8001  (Swagger: /a/v1/docs in SHARED_ENV=local)
```

Data and the model artefact are committed, so a fresh checkout works without regenerating them.

## API (CONTRACT section 6)

| Route | Purpose |
|---|---|
| `GET /a/v1/health` | liveness, no auth |
| `GET /a/v1/scenarios?include_derived=false` | scenario summaries |
| `GET /a/v1/scenarios/{id}` | full scenario (seed or derived) |
| `POST /a/v1/scenarios/{id}/disruptions` | `tanker_down` · `supply_cut` · `heat_alert` → derived scenario (201 new / 200 existing) |
| `GET /a/v1/scenarios/{id}/predictions` | XGBoost need + shortfall per area, SHAP top-3 features |
| `POST /a/v1/plans/solve` | fairness-aware CP-SAT plan with routes and reasons |
| `GET /a/v1/model` | model card: XGBoost vs last-observed baseline |

Auth: `Authorization: Bearer <HS256 JWT>` (issuer `jalpriority-b`, audience `jalpriority`, roles `dispatcher|admin|service`, 30 s leeway).
Errors use the CONTRACT 4.5 envelope with `request_id`; `X-Request-ID` is reused or generated and echoed.
`A_AUTH_DISABLED=true` exists for local tests only and **must be `false` at integration** (it is `false` by default).

## Optimizer formulation (F3, F4)

Per area `i` (shortfall `sf_i`, predicted need `n_i`, input debt `D_i`):
`U_i = sf_i / n_i`, `D̂_i = D_i / max(1, max_j D_j)`, `V_i = vulnerability_index` (0 if unavailable),
`p_i = round(1 + α·U_i + β·D̂_i + γ·V_i, 4)`.

CP-SAT works in units of 100 L over **available tankers** only: `y[k,i]` litres-units tanker *k* delivers to *i*, `z[k,i]` visit indicator.

* `x_i = Σ_k y[k,i] ≤ ⌊sf_i/100⌋` · `Σ_i y[k,i] ≤ ⌊cap_k/100⌋` · `Σ y ≤ ⌊S/100⌋`
* star route bound `Σ_i z[k,i]·2·d(depot,i) ≤ max_route_km_k` — a TSP tour over the visited set is never longer, so routes are feasible by construction
* unmet `u_i = ⌊sf_i/100⌋ − x_i = u1_i + u2_i` with `u1_i ≤ ⌈(1−φ)·sf_i/100⌉` (normal deficit) and `u2_i` the deficit **below the coverage floor φ** (`A_COVERAGE_FLOOR`, 0.25)
* minimise `Σ_i P_i·(u1_i + κ·u2_i) + Σ_{k,i} T_i·z[k,i]` with `P_i = round(p_i·1000·100)`, `κ = A_FLOOR_PENALTY` (3.0), `T_i = round(δ·d(depot,i)·1000)` (travel proxy, δ = `weights.travel`)

This is the PRD objective `Σ p·u + δ·travel` plus a soft **minimum-coverage** term that realises the PRD's "minimum neighbourhood coverage" goal.
Deliveries are multiples of 100 L; the sub-100 L remainder counts as unmet.
Stops are then sequenced per tanker by an exact TSP (≤ 7 stops, else OR-Tools routing), ties broken towards the higher-priority area first.
If CP-SAT returns nothing, a greedy-by-priority fallback answers (`engine: "greedy-fallback"`, `status: "heuristic"`, reason `TIME_LIMITED_SOLUTION`). A time limit never produces an error.

## Limitations

* Synthetic world: one service area (`sa_01`), 8 neighbourhoods, 4 tankers, one multi-stop trip per tanker per 12-hour window.
* The star-route bound is conservative: a tanker may be refused a stop set that a real TSP tour would satisfy (never the reverse).
* "Edit" a plan means adjusting weights and regenerating (CONTRACT A8); litre-by-litre manual edits are out of scope.
* Explanations are template text from structured reason codes (no LLM).
* Model metrics describe the synthetic data-generating process only.
